# CPP-005: SPSC ring buffer

Implement the C++20 `hase::SpscRingBuffer<T, Capacity>` template. It is used by exactly one producer thread and exactly one consumer thread concurrently; it is not an MPMC queue.

`try_push(T)` and `try_pop(T&)` must be non-blocking. A buffer has room for exactly `Capacity` values, reports that capacity, preserves FIFO ordering, and handles wrap-around, including when `Capacity` is one. A failed `try_push` or `try_pop` performs no queue operation; in particular, a failed `try_pop` must leave its output argument unchanged. It must support move-only values and must not require `T` to be default-constructible. If raw storage is used, each queued object must be explicitly constructed before use and destroyed exactly once, whether it is popped or remains queued when the buffer is destroyed.

Use atomics with acquire/release synchronization appropriate for SPSC ownership: once a consumer observes a successful push, it must observe the complete value written by the producer. Do not solve the task by putting a mutex around every operation or by relying solely on `memory_order_seq_cst`; the public implementation header is checked for these explicit constraints. The caller must stop both producer and consumer before destroying the buffer; concurrent destruction is outside this task's scope. Do not change the public API or add dependencies. Build and run the visible CTest suite.
